# Rain on Glass

静かな雨の日の窓を、時間をかけて眺めるためのブラウザ用シミュレーター。多くの水滴はガラスに留まり、少しずつ成長します。保持力を超えた滴が滑り始め、周囲の滴を取り込んで落ちていきます。

## 起動・検証

Node.js 20以上とnpmを使用します。外部画像・サービス・実行時ライブラリは不要です。

```bash
cd apps/rain-on-glass
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`npm run dev`で表示されるURLを開くとすぐ再生します。公開用ビルドは次の通りです。

```bash
npm run build -- --base /just-idea/rain-on-glass/
```

公開予定URL: https://tofu575.github.io/just-idea/rain-on-glass/

ルートのPagesワークフローが各アプリを独立してインストール・検証・ビルドし、`_site/rain-on-glass/`へ配置します。PRでは検証・組み立てのみ実行し、公開しません。

## 操作

操作後約5秒でタイトルとツールバーが消えます。マウス移動・タップ・キーボードのフォーカスで再表示できます。「雨の調律」から設定を開きます。

| 操作 | 内容 |
| --- | --- |
| Space / 停止ボタン | 一時停止・再開 |
| F / 全画面ボタン | フルスクリーン切替 |
| S | 設定の開閉 |
| Escape / × / 背景クリック | 設定を閉じる |
| 水滴の状態を表示 | 大きな滴の体積・速度・状態と合体数を表示 |

スライダーやボタンにフォーカスがある間は標準のキーボード操作を優先します。設定は即時反映します。水滴サイズは新着の分布・以降の成長量に作用し、既存の水滴を突然拡大しません。「静かな雨に戻す」は設定値のみ初期化し、風景を継続します。非表示タブでは物理を停止し、復帰時に経過時間を早送りしません。

`?seed=575`のようにURLで乱数シードを指定できます。同じ画面寸法・固定刻み数・設定操作なら同じ物理状態を再現します。通常は起動ごとに異なるシードです。

## 技術選定と構成

TypeScript + Vite + Canvas 2D。3DモデルやWebGL/WebGPUの利用を前提とせず、CPUだけでも屈折像を作れる構成です。UIフレームワークは使用しません。Vitestで物理モデルの不変条件を検証します。

- `src/simulation/`: DOMに依存しない水滴の生成・凝結・接触・滑落。描画とは独立した1/60秒の固定刻み。
- `src/rendering/`: 手続き生成の夕暮れの街、水膜、水滴レンズの画像化。静止滴の画像はキャッシュし、位置・大きさ・形が変わった場合だけ更新。
- `src/ui/`: 設定値、再生、全画面、操作時のみ現れるUI。
- `src/main.ts`: 更新ループ、非表示タブの処理、リサイズ。

背景は乱数配置した建物の陰と暖色・寒色の玉ぼけをCanvas上で生成し、ぼかして画素を保持します。水滴ごとに球冠を近似した法線から背景の参照位置を変えます。中央は弱い拡大、輪郭付近は急な屈折と暗い縁・方向性のあるハイライトを組み合わせ、白い円の重ね描きにはしません。落下中は速度に応じて縦に伸び、上部が少し細くなります。

## 物理モデル

接触半径を `r` として、体積の単位を `V = r³` とします（共通の球体積係数は省略）。重力は体積、保持力は接触線の長さに比例する近似により、静止限界はおおむね `r² > 定数 × 付着力 / 重力` です。個体差と座標による滑らかなガラスのむらを加えています。

- 発生は指数分布の待ち時間による非周期的な過程。小滴の半径・成長率・保持力は個別です。
- 凝結は表面積に比例する体積増加を半径の成長速度へ換算。雨量0なら新滴も凝結も停止します。
- 滑落時は静止時より低い動摩擦と速度比例の抵抗を使い、位置による摩擦の変化で加減速します。横揺れはガラス位置の滑らかなむらに従い、重力方向の運動に比べて小さくします。
- 接触判定は48pxの空間ハッシュ。滴の範囲が重なる全セルに登録し、重複した組み合わせは除外します。合体は体積と運動量を保存し、静止滴も合体で保持限界を超えると動き始めます。
- 移動滴が主となる合体では主滴の位置を維持し、接触直後の位置の飛躍を抑えます。静止滴同士は体積重み付き中心へまとめます。
- 細い通過跡は時間とともに屈折を弱めます。ときどき元の滴から体積を差し引き、跡に微小滴を残します。

## 負荷と上限

水滴は最大2,400個、水膜区間は最大2,800個。上限では新着を抑え、既存滴を突然消しません。画面下に抜けた滴と吸収された滴は削除し、描画キャッシュも解放します。初期滴数は画面面積に比例し最大1,700個。背景は横幅最大1,440px、描画DPRは最大1.5です。時間差は1フレーム最大0.1秒まで計算し、遅い環境での追いつき処理による停止を防ぎます。

リサイズは位置を画面に合わせて移し、滴の体積を維持します。背景とレンズキャッシュは再生成し、水膜はクリアします。

## 簡略化と既知の限界

- Navier–Stokes方程式や接触角の厳密解は使いません。個体ごとの保持力と滑らかな摩擦場で、静止の多い落ち着いた景色を優先しています。
- レンズはCPUの画素参照による近似です。厳密なSnellの法則、光の多重反射、色収差、背景の深度は未実装です。小滴の縁や動く光には離散的な見え方が残ります。
- 合体後の形状は新しい体積へ即時に追従します。大滴同士では膨らみが急に見える場合があり、表面張力の振動・くびれ・分裂は未実装です。
- 移動滴の中心は跳ばないことを優先するため、合体時の重心位置は厳密には保存しません。運動量と体積は保存します。
- 水膜は背景をずらして参照する視覚効果で、体積を持つ流体ではありません。水膜による接触角・付着力の変化や、水膜の吸収は未実装です。
- 多数の滴が一度に接触した場合、合体によって広がった範囲との追加接触は次の固定刻みで解決します。極端に密集した場合は空間分割でも候補数が増えます。
- 上限に達した場合、最も古い水膜区間を破棄します。強雨では通常の22秒より早く跡が消える場合があります。
- 極端に大きな画面では初期滴の密度を抑えます。動的な品質自動調整、背景プリセット、音声、ネイティブスクリーンセーバーは対象外です。

## 品質確認

`npm test`は体積・運動量保存、小滴の静止、凝結および合体を契機とする滑落、上からの巻き込み、セル境界接触、30/120fpsの一致、雨量と速度の分離、リサイズ、滴数上限、10分間の強雨での有限性と水膜上限を確認します。

Linuxのheadless Chromiumで、設定5項目・初期化・UI自動非表示・一時停止中のCanvas画素の完全一致・再開・全画面・ショートカット・390×844〜1920×1080のリサイズを確認しました。公開用ディレクトリをローカル配信し、`/just-idea/`配下の3アプリでアセット欠落と実行時エラーがないことも確認しています。

1440×900、シード575で約2.5分間連続再生した際、30秒ごとの観測で水滴は1,189〜1,516個、移動中は0〜7滴でした。合体数は183回から774回へ増加し、GC後のJSヒープは約6.4〜7.6MiBでした。公開用ビルドの別の8秒計測では平均約53fps、フレーム間隔の中央値16.7ms、95パーセンタイル33.4msでした。これらはクラウドのheadless環境の参考値で、デスクトップ実機の性能保証ではありません。

macOS/Safari、Windows、実機GPU差による品質・性能、数時間の連続再生、OS全体のメモリ使用量は未確認です。

改善候補は、合体後の輪郭緩和、水膜を使った接触角の変化、屈折の二線形補間、背景深度、低負荷なGPU描画の選択的追加です。小滴が静止する時間と、ときどき起こる連鎖を保ったまま改善してください。
